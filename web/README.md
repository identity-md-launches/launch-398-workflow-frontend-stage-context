# Daemon Sponsor frontend

One static page for the deployed `DaemonSponsorPool` (SPON) contract on Sepolia: register a worker
(approve the 100,000 SPON bond, then register), check in once per epoch, sponsor the pool
(approve, then gift), see the current epoch with countdown, budget and check-ins, list opened
epochs with the connected wallet's claimable share and a claim control, deregister and withdraw
the bond. SPON itself comes from swapping Sepolia ETH in the launch pool; the page shows a live
quote and the pool details but does not swap.

Stack: Vite 8, React 19, TypeScript 5.9, wagmi 3, viem 2, Vitest 5. The export in the repository
root `dist/` is committed and is what the publisher pins; it uses a relative base (`./`) and one
page without routing, so it works from an IPFS gateway subpath or an ENS name with no server.

## Configuration: one source of truth

Runtime configuration lives in `dist/imd-deployment.json`, generated by
`scripts/build-manifest.mjs` from the handoff copies in `deployment/`:

| File | Content |
| --- | --- |
| `deployment/handoff.json` | Copy of the workflow deployment handoff (launch ID, chain, contracts, ABI hashes, source commit, attestation) |
| `deployment/network.json` | Copy of the vetted network table (public RPC URLs, explorer, native currency, faucets, Uniswap v4 addresses, `walletAddChain`) |
| `../docs/abi/*.json` | Implementation-derived ABI arrays at the pinned source commit; copied verbatim to `dist/abi/` |

At startup the app fetches `./imd-deployment.json` next to `index.html`, validates it, fetches
each `abiPath`, recomputes the canonical Keccak-256 of every ABI (compact JSON with sorted keys)
and refuses to show contract controls if anything disagrees with the attested hashes. Addresses,
chain ID, RPC URLs, explorer, Uniswap v4 addresses and the `wallet_addEthereumChain` parameters are
all read from that file at runtime; nothing in `src/` hard-codes a deployment value. The only
build-time constants are `src/generated/abis.ts` (TypeScript inference types generated from the
same ABI files, hash-checked against the runtime ABI at startup) and the deployment block used as
the start of log scans, also generated from the handoff.

There are no private credentials. Reads use the public RPC list with fallback; signing stays in the
visitor's wallet. Browser wallets are discovered through EIP-6963 plus the legacy `window.ethereum`
provider. No WalletConnect project ID is configured; to add one, create a `walletConnect` connector
in `src/wagmi.ts` with the public project ID and pass it alongside `injected()`.

## Commands

```sh
cd web
npm install            # installs from package-lock.json (Node 22 or 24)
npm run build          # gen ABI types -> typecheck -> vite build to ../dist -> write dist/imd-deployment.json
npm run verify:dist    # independent check of the committed export against deployment/handoff.json
npm test               # Vitest: config validation, formatting, epoch math, chain switching, mocked wallet flows, export integrity
npm run check          # typecheck + test + verify:dist
npm run dev            # dev server (needs ../dist/imd-deployment.json to exist: run a build first)
npm run preview        # serves the built export locally
```

`npm run manifest` rewrites only `dist/imd-deployment.json` and `dist/abi/` after an export change.
Any change to `src/`, `deployment/` or the ABI files requires `npm run build` and committing the
new `dist/` together with the source. `npm run preview` serves at a root path; to check the
subpath case, serve `../dist` under any prefix (the review script in `docs/frontend-validation.md`
did so under `/preview/`).

## What the page does

- **Header**: connect controls for each detected wallet, connected address with explorer link,
  network pill, a single "Switch to Sepolia" control when the wallet is on another chain
  (`wallet_switchEthereumChain`, then `wallet_addEthereumChain` with the vetted parameters on
  code 4902 or an "unknown chain" message, then switch again), and Disconnect.
- **Current epoch**: epoch number, whether it has been opened (from `EpochRolled` events),
  countdown to `genesis + (epoch + 1) * EPOCH_DURATION` anchored to the latest block timestamp,
  budget (or the estimate the next transaction would reserve), check-ins, pool, reserved rewards
  and bonds held.
- **Your wallet**: SPON balance, allowance granted to the pool, worker status and this epoch's
  check-in state.
- **Worker**: approve bond → register; check in; deregister (inline confirmation); withdraw bond
  with the unlock epoch and time shown while locked.
- **Sponsor**: decimal amount, approve → sponsor, with balance and allowance shown.
- **Past epochs**: opened epochs newest first from `EpochRolled`, the wallet's participation from
  `CheckedIn` (both read in bounded block chunks from the deployment block, halving the range on
  RPC errors), share from `claimable`, and a claim control per unclaimed past epoch.
- **Get SPON**: live quote from the network's Uniswap v4 quoter (read-only `simulateContract`,
  never a transaction), pool key, pool ID, PoolManager, Universal Router and Quoter addresses.
- **Contracts**: every deployed address with explorer link, launch ID, source commit, attestation
  hash and the public RPC hosts. If `token()` ever differs from the manifest's token address the
  page shows an alert.

Every transaction is simulated first; revert reasons (custom errors such as `AlreadyCheckedIn` or
`BondLocked`) and wallet rejections are shown in a live status region with an explorer link once a
hash exists. Controls are disabled with a visible reason while the wallet is disconnected, on the
wrong chain, or the contract state does not allow the action.
